# Client Decisions

## Purpose
To keep a permanent, dated record of every meaningful decision the client has made, so the reasoning behind the current build is traceable and doesn't rely on anyone's memory.

## Overview
This log complements `MEETING_NOTES.md` (which captures full conversations) by isolating just the decisions themselves in a scannable format.

## Current Status
Log initialized with foundational decisions from project scoping; updated as further decisions are made.

## Responsibilities
Maintained by the developer; every decision entry should be confirmed with the client (in writing, where possible) before being logged as final.

## Implementation Notes

### D-001 — Engagement Scope
- **Date:** Project scoping
- **Decision:** Scope limited to public website + CMS + Enquiries + basic SEO; booking, payments, CRM, and advanced security deferred to a future phase.
- **Reasoning:** Matches current budget (fixed fee of USD $150) and immediate business need (professional web presence + centralized enquiries), without over-building for features not yet needed.

### D-002 — CMS Approach
- **Date:** Project scoping
- **Decision:** Build a bespoke CMS on Supabase rather than integrating a third-party headless CMS.
- **Reasoning:** Keeps ongoing costs at zero beyond Supabase's own pricing, and matches the modest scope of a six-page site.

### D-003 — Design Direction
- **Date:** Project scoping
- **Decision:** Elegant, editorial, minimal aesthetic — soft neutral palette, restrained motion, serif/sans type pairing.
- **Reasoning:** Matches the client's luxury positioning; confirmed against reference imagery during scoping.

### D-004 — Payment Terms
- **Date:** Agreement execution
- **Decision:** 50/50 split — 50% before development starts, 50% before final handover.
- **Reasoning:** Standard freelance protection for both parties; formalized in the signed Website Development Agreement.
