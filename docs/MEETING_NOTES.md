# Meeting Notes

## Purpose
To keep a running, dated record of client meetings and calls, so decisions and context aren't lost to memory or scattered chat threads.

## Overview
Every substantive client conversation (scoping, feedback rounds, handover planning) should be summarized here shortly after it happens, even briefly, distinct from `CLIENT_DECISIONS.md` which logs only the resulting decisions.

## Current Status
Log initialized; first substantive entry pending the next scheduled client meeting.

## Responsibilities
Maintained by the developer; summaries should be factual and brief, not verbatim transcripts.

## Implementation Notes
**Template for new entries:**

### [YYYY-MM-DD] — [Meeting Topic]
- **Attendees:** [Names/roles]
- **Summary:** [2–4 sentence summary of what was discussed]
- **Decisions Made:** [Link to relevant `CLIENT_DECISIONS.md` entries if applicable]
- **Action Items:** [Who owns what, by when]
